# Alazab Daftra Toolbox — Foundry OpenAPI

هذه حزمة إعداد قابلة للمراجعة وليست نشرًا منفذًا. المصدر هو Default module.openapi(1).json المرفق: 301 عملية عبر 206 مسارات. تعليمات تقرير 66 تقريرًا في وصف المصدر لا تعكس قائمة المسارات الفعلية، ولذلك لم تستخدم لتعريف نطاق الأدوات.

## المحتويات
- specs/: 21 مواصفة OpenAPI 3.0.1 تغطي 266 عملية مرشحة؛ تحتوي عناوين .invalid عمدًا حتى التهيئة.
- review/: تعريف منفصل لكل العمليات الـ301، بما فيها 35 عملية معلقة مع أسبابها.
- references/operations.csv وoperations.json: سجل كامل بالمسار والطريقة والأثر والحالة.
- AGENT_INSTRUCTIONS_AR.txt: تعليمات تشغيل API الحي، تضاف لتعليمات az-agent-sol.
- backup-skill/: SKILL.md وملفات النسخة الأصلية ومراجعها وأداة الفحص. تستخدم عند تحليل CSV، ولا تستبدل API الحي.
- scripts/configure.py: يضبط العناوين والاتصال ويولد ملفات الاستيراد والطلب الخاص بإنشاء Toolbox.
- scripts/create_toolbox.sh: يرسل طلب إنشاء إصدار Toolbox فقط عند تشغيله صراحة.
- references/validation.json: نتيجة فحص البنية، وليست اختبارًا لاتصال حي.

## ما تم إصلاحه
إنشاء operationId فريد لكل عملية، إزالة خادم Mock الفارغ، فصل بيانات المصادقة عن مدخلات النموذج، توحيد مخطط اتصال التوكن أو apikey، إزالة أمثلة التصدير، تصحيح maxLength النصية وtype:double، وتحويل type:null إلى قيد null دون تخمين النوع الحقيقي. إزالة معاملات المسار الزائدة التي لا يقابلها متغير في المسار. إزالة جسم GET الفارغ غير المطلوب لمعلومات الموقع. الاحتفاظ بمكونات responses المشار إليها.

المسارات التي تنص أوصافها صراحة على قاعدة /v2/api/entity لها server مستقل على مستوى العملية. عند التهيئة تتحول لاحقة {format} الملحقة بالاسم إلى .json؛ أما /{format} كجزء مستقل فتبقى معاملًا لأن معناها في تلك المسارات مختلف. لا تعامل dataLevel كرقم صفحة.

## ما يحتاج استكمالًا
35 عملية معلقة بسبب مسارات متعارضة شكلًا، أو /id مكتوبة كقيمة حرفية، أو تضارب قاعدة /v2 مع /api2، أو GET له جسم فعلي، أو طلب multipart/text. لم نحول الطرق أو الأجسام إلى JSON بالتخمين. عملية OAuth نفسها لا تدخل أدوات العمل؛ الاتصال الحالي مسؤول عن تمرير التوكن، وتجديده مسؤولية إدارة المصادقة.

## الإعداد
1. حدد قاعدة api2 الحقيقية لحساب دفترة وقاعدة native entities. لا تستنتج اسم الحساب من Alazab أو دومينات الشركة.
2. أنشئ أو استخدم اتصال Foundry من نوع Custom keys. المسار الأساسي المقترح للمصدر الحالي: اسم المفتاح Authorization وقيمته Bearer ثم مسافة ثم التوكن. لا تختَر Anonymous. إذا كان حسابك يستخدم apikey فعليًا اختر --auth-header apikey واضبط الاتصال بالاسم نفسه. يجب إثبات أن نوع المصادقة يدعم العمليات المطلوبة؛ اختيار flag لا يثبت ذلك.
3. من مجلد الحزمة نفذ، بعد استبدال القيم التالية بقيم مؤكدة:

```bash
python3 scripts/configure.py \
  --base-url 'https://YOUR-TENANT/api2' \
  --entity-base-url 'https://YOUR-TENANT/v2/api/entity' \
  --connection 'YOUR-FOUNDRY-CONNECTION' \
  --auth-header Authorization
```

سينشأ configured/ وفيه ملفات OpenAPI لاختيارها في شاشة OpenAPI tool، وtoolbox.request.json لإنشاء Toolbox واحد يحتوي المجموعات الـ21. عند الرفع عبر الشاشة استخدم اسم المجموعة واختر اتصال المصادقة المطابق. لا ترفع ملفات specs قبل التهيئة.

4. لإنشاء Toolbox عبر REST بعد ضبط FOUNDRY_PROJECT_ENDPOINT وAGENT_TOKEN في بيئتك:

```bash
bash scripts/create_toolbox.sh
```

المتغير الأول endpoint المشروع من صفحة Overview، وليس endpoint chat completions. السكربت ينشئ إصدارًا جديدًا ولا يعدل وكيلك تلقائيًا. احتفظ بمعرف الإصدار من الرد ثم اربط Toolbox بالوكيل عبر واجهة Foundry، وأضف محتوى AGENT_INSTRUCTIONS_AR.txt إلى التعليمات الحالية دون حذف سياق المشروعات الأخرى.

5. اختبر معلومات الموقع أولًا ثم قائمة عملاء وعرض عميل بمعرفه. اختبر صلاحية مسار entity بعملية قراءة كذلك قبل تمكين العمل عليه. تحقق من أدوات Toolbox المكتشفة وعددها ونجاح المصادقة. لا تختبر الكتابة بإنشاء فواتير فعلية في الإنتاج؛ استخدم بيئة اختبار معتمدة أو مهمة حقيقية مأذونًا بها.

6. احتفظ بإرشادات النسخة الاحتياطية في سياق الوكيل حين يحلل ملفات CSV. لا يلزم إرفاق CSV لتشغيل API حي، ولا رفع SKILL.md وحده يفعّل أي اتصال أو أداة.

## حدود التحقق
تم فحص مواصفات المصدر المعدلة والمخرجات المهيأة عبر openapi-spec-validator. لم يجر اتصال بحساب دفترة، أو إنشاء مورد Foundry، أو اختبار قبول الخدمة لهذه العمليات. نجاح التحقق البنيوي لا يثبت دقة كل وصف في ملف المصدر ولا توافق الحساب والنموذج والمنطقة. معاملات اختيارية ذات نوع مجهول في المصدر لا تصبح صالحة بفضل التعليمات؛ تحتاج توثيقًا فعليًا عند استخدامها.
