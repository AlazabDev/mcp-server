# مركز تكاملات العزب — تطبيق Frappe 16

تطوير مباشر لتطبيق `mcp_server` الموجود داخل `mcp-server.zip`. التطبيق يعمل داخل عملية Frappe وقاعدة بيانات الموقع. لم يعد يحتاج خدمة Python مركزية منفصلة أو منفذ 8780. مصادر `az_mcp` المرفقة محفوظة، وتستخدم كتالوجات العمليات وتعليمات دفترة وقارئ CSV الفعلي منها.

## المكونات

- صفحة عربية في `/app/mcp-center` ومساحة عمل واختصار تطبيق.
- سجلات `MCP Plugin` و`MCP Skill` و`MCP Connector` و`MCP Capability`.
- سجلات `MCP Execution Log` و`MCP Connection Test`، مع الإعدادات وقائمة المستندات والحقول الأصلية.
- 13 بلجنًا و18 موصلًا و371 قدرة مسجلة و5 مهارات. الرقم يشمل القدرات غير المفعلة ورفع الوسائط غير المدعوم؛ ليس عدد الاتصالات الحية.
- تفعيل الموصل والبلجن والقدرة وأدوار المستخدم شروط فعلية للظهور والتنفيذ. عمليات الكتابة تحتاج إذن الموصل والمفتاح العام للكتابة وصلاحيات مستند Frappe.
- Native Frappe OAuth/API keys، مع دعم التوكن القديم عبر `X-MCP-Token` عند اختيار النمط القديم صراحة.
- MCP stateless JSON عبر نفس WSGI والـ transaction في Frappe؛ أدوات وPrompts وResources ومؤشرات صفحات.

## التثبيت أو ترقية التطبيق الموجود

تستخدم هذه الحزمة Python 3.14 مثل إصدار Frappe 16.52.0 الذي تمت مراجعة كوده. لا تغيّر إصدار Python لبيئة إنتاج قائمة؛ راجع تطابق Bench أولا. إدارة Frappe وMariaDB وRedis تبقى عند Bench.

فك الحزمة خارج مجلد Bench، ثم نفذ باسم مستخدم frappe:

```bash
bash /path/to/mcp_server/install_frappe16.sh /home/frappe/frappe-bench erp.alazab.com
```

السكربت يعمل نسخة احتياطية للموقع ونسخة من التطبيق الموجود، ويحافظ على ملفات إعداد التكاملات المثبتة. يشغّل migrate عند وجود التطبيق وinstall-app عند غيابه. لا يحذف apps أو sites، ولا يغير Nginx أو بقية التطبيقات. لا ينفذ restart عام تلقائيا؛ أعد تشغيل مجموعة خدمات Bench بالطريقة المعتمدة في سيرفرك.

عند تثبيت التطبيق داخل Bench يدويًا يمكن تثبيت متطلباته بـ `env/bin/pip install -e apps/mcp_server` ثم تسجيل اسمه في sites/apps.txt وتثبيته بأمر Bench المعتاد. يجب نسخ مجلد التطبيق كاملا، بما فيه az_mcp.

## الاستخدام داخل Frappe

1. افتح `/app/mcp-center` بحساب System Manager. أضف دور MCP Manager لمن يدير التكاملات ودور MCP Operator لمستخدمي الأدوات.
2. افتح إعدادات خادم MCP وحدد رابط الموقع المنشور الصحيح إن لم يكن host_name مضبوطا.
3. راجع الموصلات. بيانات الاتصال الموجودة في ملفات env المرفقة تُستورد عند أول تثبيت إلى حقول Password في Frappe، دون استبدال المفاتيح المسجلة. زر استيراد الإعدادات يعيد العملية عند الحاجة، ولا يعرض القيم.
4. الموصلات الخارجية لا تُفعّل تلقائيًا لمجرد وجود مفتاح. اختبر الموصل ثم فعّله. لخدمة تحتاج POST للاستعلام مثل UberFix، اختر قدرة فحص القراءة الاختيارية وأدخل JSON الفحص في نموذج الموصل. نتيجة الاختبار الناجح ليست ضمانًا لصلاحية كل عملية أو كل نطاق.
5. الموصل المحلي ونسخة دفترة التاريخية متاحان بعد التثبيت. قراءة النسخة التاريخية تتطلب MCP Manager أو System Manager.
6. لكل قدرة مخطط JSON وزر اختبار تنفيذ بمدخلات صريحة. سجل التنفيذ يحفظ معرف الطلب والمستخدم والعملية والمدة والنتيجة وبصمة المدخلات، دون نسخ كامل المحتوى.
7. إيقاف بلجن يمنع مهاراته وأدواته عبر MCP. تعديل مهارة يُقرأ من قاعدة البيانات في الطلب التالي؛ لا يلزم تعديل ملفات على السيرفر.

## ChatGPT

نقطة الاتصال تكون على نفس موقع Frappe:

```text
https://erp.alazab.com/api/method/mcp_server.transport.handle
```

الخطوات:

1. من تبويب اتصال ChatGPT فعّل اكتشاف OAuth الأصلي. لا يُنشأ خادم هوية خارجي، ولا يُفتح تسجيل العملاء الديناميكي تلقائيا.
2. أنشئ OAuth Client داخل Frappe. استخدم Authorization Code وPKCE S256، والنطاق المناسب مثل all/openid وفق إعدادات Frappe. انسخ **عنوان الرجوع الفعلي** الذي تعرضه واجهة ChatGPT؛ لا تستخدم عنوانا ثابتا مخمنا.
3. أدخل رابط MCP وبيانات العميل المسجل في واجهة التطبيق المخصص في ChatGPT. اختيار client_secret_basic أو none يجب أن يطابق نوع العميل المسجل. المصادقة تتم بمستخدم Frappe؛ امنحه دور MCP وصلاحيات المستندات المطلوبة.
4. أكمل تسجيل الدخول ثم اطلب `central_status` و`central_list_skills` و`central_get_plugin` بمعرف البلجن.
5. اقرأ المهارة عبر `central_get_skill` ثم نفذ الأداة المناسبة. تعليمات المهارة ليست برنامجًا يشغّل نفسه؛ النموذج يستخدمها لتنظيم طلبات الأدوات. رفع الحزمة إلى السيرفر لا يثبت التطبيق في حساب ChatGPT تلقائيا.

التوكنات يتحقق منها Frappe نفسه، بما في ذلك صلاحيتها وهوية المستخدم. endpoint الخاص بوصف المورد هو `/api/method/mcp_server.transport.resource_metadata`، ويُعلن في WWW-Authenticate. بيانات authorization server الأصلية في `/.well-known/oauth-authorization-server`.

للعملاء المحليين يمكن استخدام `Authorization: token API_KEY:API_SECRET` لمستخدم Frappe مصرح له. لا يُستخدم مفتاح OpenAI أو اشتراك ChatGPT كمفتاح دخول إلى Frappe.

## الخدمات والقدرات

- **دفترة:** 301 عملية من catalog.json؛ يدعم المصادقة apikey أو Bearer حسب حسابك. بعض عمليات GET الأصلية تغيّر حالة؛ صُنفت ككتابة.
- **magicplan:** المخطط الحقيقي 41 عملية؛ هيدر key وcustomer عند احتياجه.
- **UberFix:** مخطط بوابة الصيانة، مع قدرة منفصلة محصورة بـ get_status للقراءة.
- **Meta WhatsApp:** المخططات الثلاثة المرفقة؛ معلمات graph_version/business_id/waba_id/phone_number_id من إعداد الموصل. رفع الوسائط multipart غير مفعّل؛ بقية العمليات حسب مخططها وصلاحيات الحساب. التطبيق لا ينشئ Webhook لاستلام صور واتساب في هذه النسخة.
- **نسخة دفترة:** جرد واستعلام محدود عن CSV بالقارئ الأصلي الذي يعالج BOM. ترجع النتائج live=false. لا تُستورد الفواتير إلى ERPNext تلقائيا.
- **OpenAI وAnthropic وGemini وAzure OpenAI وواجهات OpenAI المتوافقة/Ollama:** توليد نص عبر مفتاح الخدمة ومعرف نموذج تختاره. Azure يستخدم عنوان OpenAI v1 للنشر المناسب. دعم النموذج الفعلي يختبر من القدرة؛ بعض المزودين يحتاجون معلمات خاصة غير موجودة في الواجهة الموحدة.
- **Supabase وFoundry والبريد والنماذج والتخزين وGoogle Cloud وOracle:** سجلات Remote MCP مهيأة للإعداد، مع بقاء ملفاتها الأصلية. ضع عنوان خدمة MCP العاملة ومصادقتها، ثم مزامنة الأدوات. لا تدعي الحزمة وجود endpoint حي أو بناء خدمات ناقصة في تلك المصادر.
- **خدمة HTTP جديدة:** أنشئ موصل HTTP API وقدرات نسبية إليه بمخططات JSON. لا يُقبل عنوان خدمة من مدخلات استدعاء الأداة.

الموصل البعيد يدعم Streamable HTTP بمفتاح/توكن محفوظ، وليس تشغيل أوامر stdio أو تثبيت npm داخل عامل Frappe. شغّل الخادم المرفق المعتمد على stdio كخدمة HTTP مستقلة ثم سجّل عنوانه. إدارة OAuth الصادر وتجديد توكنات تلك الخدمات ليست مؤتمتة؛ OAuth الأصلي هنا لاتصال ChatGPT الوارد.

## بوابة Git قبل البناء الآلي

الملف `.github/workflows/validate.yml` يفحص كل Push وPull Request دون مفاتيح اتصال: تثبيت Editable من المصدر، سلامة ملفات التطبيق، بناء توزيعات Python، عقود الموصلات والواجهة العربية. يجب جعل نجاح `source-build` شرطًا لدمج التغييرات في فرع النشر. لا ينشر هذا الفحص إلى السيرفر.

المسار المعتمد في Bench هو مصدر Git كامل مثبت بطريقة Editable (`bench get-app`)، وليس تثبيت Wheel منفردًا؛ ملفات التكامل الأصلية `az_mcp` جزء مطلوب من المصدر. ملفات البيئة اختيارية ولا تلزم للبناء؛ يقرأها التطبيق عند وجودها فقط.

بعد اجتياز الفحص، تظل مرحلة اختبار `install-app` و`migrate` و`bench build --app mcp_server` على Bench تجريبي مطابق للسيرفر شرطًا لاعتماد الإصدار للنشر الآلي. فحص Git وحده لا يختبر إعدادات السيرفر أو قاعدة بيانات الإنتاج.
